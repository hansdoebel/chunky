# Dataset benchmarks and test collections

Download a public Hugging Face snapshot in the Datasets window. In Benchmark, choose **Use downloaded dataset…**, select that snapshot folder, then choose a string text field. The default is the first 100 rows; the maximum is 1,000 rows, 32 KiB of text per row and 8 MiB total. Empty, missing or oversized text fails with a specific error instead of being silently skipped or truncated. The snapshot hash and pinned dataset revision are checked again before use. Validation and text extraction run away from the UI thread and can be cancelled.

The run uses the current embedding provider and model from Preferences through the existing Ollama, OpenAI-compatible or local CPU FastEmbed service. It runs from the Mac, even when document processing is configured for a worker. An endpoint may still be remote. One document and query warm-up validates matching dimensions before a timed document embedding pass. No Docling conversion is performed and no client embedding cache is used; provider caches may already be warm. The displayed timings and saved JSON report contain the dataset revision, configuration, split, row-file hash, selected field, row count, configured provider/model and observed dimensions. They are throughput measurements, not recall, MRR or other quality scores. Dataset rows do not imply relevance labels. Existing PDF benchmarks and imported embedding comparisons remain available.

**Also fill a new Qdrant test collection** explicitly writes real generated vectors to the Qdrant endpoint configured in Preferences. Each run generates a new `chunky-dataset-test-<UUID>` name. Creation is atomic and fails if that name already exists; production collections are never reused or reconfigured. The collection is dense cosine with the validated dimensions. A matching model plan is saved for browsing and retrieval, without changing the selected production collection or provider settings. Points include source revision, row index, field and hash provenance, and `chunky_test_data=true`. Test points use the default paper library; select Default when browsing them.

Cancel stops between provider requests or write batches. A cancelled or failed seed may leave an empty or partial test collection, whose name appears in the status. It is preserved for inspection and never automatically deleted. Remove test collections deliberately through the normal collection UI when no longer needed. An embedding-only run never connects to or modifies Qdrant.

For a first MacBook check, use a small public text corpus, select a text field, and run 10–100 rows with the local CPU provider or an already installed Ollama model. Run embedding-only first, then enable test collection filling after Qdrant is reachable. Save the report to compare repeated runs with the same dataset hash and configuration. Native screenshot fixtures demonstrate the UI only; their numbers are not benchmark evidence.
